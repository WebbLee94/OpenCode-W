# DBScope-OC 三重视角体验审查报告

> 体验范围：完整 7 个主模块（首页仪表盘 / 会话浏览 / 消息查看 / 待办 / 账户 / 清理 / 备份 / 分享），覆盖 1.0.x 在用的设计稿与实际运行截图。
> 视角：产品经理 PM（功能闭环与价值主张） · 天使用户 Early Adopter（首次接触的认知与情绪曲线） · UI 视觉设计师（视觉语言、信息密度、视觉层次）。
> 日期：2026-06-12

---

## 一、TL;DR — 一句话总结

**这是一个"功能堆叠正确、但产品语言尚未建立"的工具型应用**。核心数据流（浏览 → 搜索 → 清理 → 备份）是顺畅的，但在「欢迎感、引导感、品牌感、错误温柔度」四个维度上明显欠缺。把它从"开发者用得上"提升到"非技术 OpenCode 用户也敢用"，需要在 **首屏体验 + 错误体系 + 视觉一致性 + 信息架构** 四个层面进行系统性补课。

整体评分（5 分制）：

| 视角 | 评分 | 一句话 |
|------|------|--------|
| 产品经理 PM | **3.4 / 5** | 功能骨架完整，但缺少引导、解释、信任建立与价值放大 |
| 天使用户 | **3.0 / 5** | 第一眼会"愣住"，操作流畅度尚可，恐惧感来自破坏性操作与未脱敏的错误 |
| UI 视觉设计师 | **3.1 / 5** | 基础色板与组件尚可，但缺乏品牌语言、层级混乱、留白与节奏感差 |

## 二、天使用户视角（Early Adopter First-Look）

> 假设读者：第一次听说 OpenCode 但用过 AI 工具的普通用户，刚 `git clone` 跑起来。

### 2.1 第一眼进入应用

- **现状**：打开 App，看到一个紫色 Logo + "Database Manager" 副标题，7 个导航项罗列在侧边栏。主区只有一条灰色虚线图标 + **"No Database Connected · Select an OpenCode SQLite database to get started."** 和一个紫色 "Connect Database" 按钮。
- **情绪曲线**：困惑 → 轻微焦虑（"我没有 opencode.db 怎么办？"）。
- **问题**：
  1. 没有任何 "OpenCode 是什么" "这工具能帮你做什么" 的引导文案或截图预览。
  2. 按钮文案是英文 **"Connect Database"**，但应用其他位置几乎全中文，**语言不统一** 严重破坏专业感。
  3. 没有提供 "帮助我们自动定位数据库 / 拖拽文件到此处即可打开" 的次级引导。
  4. "Database Manager" 副标题对小白用户太技术 —— 他们连 SQLite 都不一定知道。

### 2.2 进入会话浏览页（无数据时）

- **现状**：标题 "Sessions" 是英文，右侧 "共 0 条会话" 提示正确。但表头、按钮也都是英文，主体空状态只有一行 "暂无会话数据"。
- **问题**：
  1. 标题 "Sessions" 没翻译，**主标题语言混用** 是低级体验事故。
  2. 空状态太单薄 —— "暂无数据" 四个字解决不了用户的 "那我该怎么办？"，应该给出 "导入示例数据 / 打开其他数据库 / 跳转到备份" 等次级出口。

### 2.3 进入清理向导（最危险的一步）

- **现状**：3 步进度条 + 4 个策略卡片 + 友好的图标。整体体验是全应用最专业的。
- **亮点**：
  1. 步骤指示器清晰，符合用户对"向导"的预期。
  2. 3 秒倒计时 + 勾选"已备份"双重确认，做对了。
  3. 策略卡片用图标 + 标题 + 描述 + 立刻展开参数，**信息密度恰到好处**。
- **恐惧点**：
  1. **"自定义 SQL WHERE 条件"** 对非开发者是黑洞 —— `s.time_created < ?` 这种写法天然屏蔽了 80% 的用户。应该默认折叠/隐藏、并在用户主动开启时给出更明确警告："你将直接修改数据库，请确保你知道 WHERE 子句的含义"。
  2. 步骤 2 跳到步骤 3 之后，**没有"返回上一步"后保留勾选状态**的预期（实际是保留了，但用户感知不到）。

### 2.4 进入备份恢复页

- **现状**：一张白卡 "创建备份"，一个紫色 "立即备份" 按钮，下方 "备份列表" 标题 + "暂无备份文件" 空状态。
- **亮点**：
  1. "备份目录：~/.DBScope-OC/backups/" 直接展示，**透明、可信**。
  2. 顶部有一个 "自动备份设置 · 启用" 复选框但**没有任何附加说明**（什么频率？保留几天？存哪里？）。
- **问题**：
  1. **"自动备份设置"是个空壳** —— 勾上没有任何变化，没有频率/保留策略/加密选项，相当于"骗用户"。
  2. 红色报错 "Electron API 不可用。请在 Electron 窗口中使用此应用，而不是浏览器。请运行 npm run dev 启动 Electron 应用。" —— 这条错误是开发者的而不是用户的，在生产环境会让终端用户**极度恐慌**（以为是数据损坏了）。

### 2.5 整体情绪曲线评分

| 阶段 | 情绪 |
|------|------|
| 启动 | 困惑（"这是什么"） |
| 首次进入主页面 | 焦虑（"我没有数据"） |
| 浏览数据 | 顺畅（如果已有 opencode.db） |
| 看到红色错误 | 恐惧 |
| 准备清理 | 紧张 |
| 备份 | 安心（仅在不出错时） |
| 关闭前 | 平静但无记忆点 |

## 三、产品经理视角（PM Functional Audit）

### 3.1 产品定位与价值主张

- **定位**："OpenCode 数据库可视化管理工具"。
- **问题**：定位过于"功能描述"，没有"用户收益描述"。
- **建议改写为**：
  - 主标语：**"你的 OpenCode 数据，一目了然 · 可控可管不再丢失"**
  - 副标语：让普通用户也能像查相册一样浏览、回溯、清理与备份自己与 AI 的对话资产。

### 3.2 功能闭环分析

| 模块 | 闭环度 | 主要缺口 |
|------|--------|----------|
| 仪表盘 | ⭐⭐⭐⭐ | 缺少"异常告警"（如某天用量暴增）、缺少"对比基线"（比上周期 ↑↓） |
| 会话浏览 | ⭐⭐⭐⭐ | 缺少"快速标签"（置顶/星标/归档）、缺少"批量操作"（多选删除/导出） |
| 消息查看 | ⭐⭐⭐ | 跨 Session 搜索入口埋得深；缺少"原文/渲染切换"、"复制"按钮 |
| 待办 | ⭐⭐ | 与 OpenCode 主流程的耦合度低，没法和 Session 双向跳转 |
| 账户 | ⭐⭐ | 没有任何"切换账户 / 复制 token / 续期"操作，纯展示 |
| 清理 | ⭐⭐⭐⭐⭐ | 是全应用最完整的功能，建议将"清理策略"沉淀为"预设 + 自定义" |
| 备份 | ⭐⭐⭐ | "自动备份"是空壳；"恢复"流程缺少原库备份（恢复后回不去老库） |
| 分享 | ⭐ | 完全是"占位页"，应该明确说明状态 / 灰度原因 / 预期上线 |

### 3.3 缺位的"产品级"能力（按重要性 P0 → P2）

**P0（必须补）**
1. **首屏"零数据"状态**：从"选择数据库"升级为"5 秒引导 —— 演示数据 / 自动定位 / 帮助文档" 三选一。
2. **错误信息脱敏**：禁止向用户暴露 "Electron API 不可用" 这类开发者术语，统一为"无法连接到本地数据库服务"+"重试 / 反馈"两个按钮。
3. **会话批量操作**：单条删除体验太繁琐，用户清理 100 条会话会疯。需要多选 + 批量删除/导出/打标。
4. **自动备份真实化**：要么做完整（频率 / 保留数 / 加密），要么从 UI 移除。

**P1（强烈推荐）**
5. **会话标签 / 星标 / 归档**：用户一定会想"这条对话重要不能删"。
6. **跨 Session 全文搜索**：当前入口在 "消息查看器"，应该在顶部 Header 全局可触达。
7. **消息导出（Markdown / JSON / PDF）**：开发者社区工具的标配。
8. **键盘快捷键**：Cmd+K 调出全局搜索、Cmd+1..7 切换侧边栏模块 —— 工具型应用的"专业感"重要来源。

**P2（可沉淀）**
9. **变更历史 / 操作日志**：清理 / 恢复 / 删除都应该有审计记录。
10. **数据洞察**（不是"统计图表"）：如"你的高频 Token 浪费来自哪类 Session"、 "哪些 Skill 实际上没用过"。

### 3.4 商业模式与产品增长角度

- 当前是单机工具，缺乏"用户故事"和"使用分享"机制（"分享管理"模块名占位了，但实际是空页面）。
- 建议引入 "匿名使用洞察" 帮团队迭代（明确告知用户、可关闭），同时为后续 SaaS 化或 OpenCode 插件化留口。

## 四、UI 视觉设计师视角（Visual & Interaction Design）

### 4.1 整体视觉印象

- **色板**：紫色 `#8b5cf6` / 蓝色 `#3b82f6` / 灰色阶，功能色（红/橙/黄/紫）覆盖到位。
- **优势**：配色冷静、克制，不像某些 AI 工具"赛博朋克"风；可读性高。
- **劣势**：
  1. **品牌识别度弱**：除了一个紫色渐变 Logo，没有"专属色 / 专属图形 / 专属字体"。
  2. **同色滥用**：紫色既是 Logo 色、又是 "Skill" 色、又是 "活跃态" 强调色，**色彩语义混淆**。
  3. **没有 Dark Mode**：开发向工具默认应该有 Dark Mode（参考 TablePlus / Beekeeper Studio）。

### 4.2 信息密度与节奏

- **优点**：
  - 仪表盘 6 行分区（数据库概览 / 时间范围 / 时段统计 / Token / 增长趋势 / 工具 & 技能）层次清晰。
  - 统计卡片 + 图表 + 列表的三段式符合"先看数 → 看趋势 → 看明细"的认知曲线。
- **问题**：
  1. **图表区间高度不一致**：Token 饼图和增长趋势图并排，但高度不统一会显得"拼接"。
  2. **统计卡片信息过载**：单卡同时显示"图标 + 标题 + 大数字 + 小注释 + 次级小数字"，建议用"卡片颜色区分"或"鼠标 hover 显示详情" 来降噪。
  3. **空白太多 = 不专业**：当数据为空时，几乎整个屏幕都是灰白，**让人怀疑应用是否加载完成**。

### 4.3 组件语言一致性

| 元素 | 现状 | 问题 |
|------|------|------|
| 按钮 | 主紫、次白、危险红 | OK，但缺少"幽灵按钮"、"链接式按钮"，导致次要操作（比如"重置筛选"）被迫用大按钮 |
| 表格 | 简洁、Tailwind 默认 | 缺少斑马纹、缺 sticky 表头，长列表体验差 |
| 模态框 | 有 `Modal` 组件 | OK，但备份恢复的"二次确认"和清理的"二次确认"样式不一致 |
| Toast | 存在 | OK |
| Badge | 存在 | OK |
| 步骤条 | 清理向导的进度条 OK | 但只在这一处用，建议抽出作为标准组件 |
| 空状态 | 每页都有 | 缺统一插画 / 缺行动建议（详见 §2） |
| 加载态 | 部分页面有骨架 | 不全，仪表盘刷新时是"白屏 + Toast" |
| 错误态 | 是的 | **但直接把堆栈抛给用户**（见 §5） |

### 4.4 文字与排版

- **字体**：使用系统默认中文字体，未引入 Inter / 思源黑体等专门字体，导致 Linux/Windows 与 macOS 视觉差异大。
- **层级**：H1（页面标题）字号偏小、字重不够强（dashboard "Dashboard" 看上去只是普通文字），缺乏"页面感"。
- **混排**：英文 "Sessions / Backup / Cleanup" 与中文 "首页仪表盘 / 备份恢复" 交替出现，**专业感被破坏**。

### 4.5 交互细节

- **侧边栏导航**：没有"折叠"按钮，当窗口缩小到 800px 时会被挤压。
- **空状态图标**：用的是 lucide 的通用图标，缺少品牌定制的"零状态插画"。
- **详情面板**：会话点击打开右侧 480px 面板，但**没有"全屏"或"在新窗口打开"** 的扩展入口。

### 🔴 P0 — 立即必须改

## 六、推荐的"先做哪 3 件事"

如果你只能动 3 件事，建议按这个顺序：

1. **建立"零状态系统"**（覆盖首屏 + 7 个模块空状态 + 错误态）
   → 解决 60% 的"小白看不懂"问题。
2. **落实"自动备份"**（或从 UI 移除）
   → 解决"看起来很专业但实际是空壳"的最大信任危机。
3. **全局快捷键 + 全局搜索**
   → 用最小成本把"工具感"拉满，建立早期使用习惯。

## 七、写在最后

DBScope-OC 已经具备了**扎实的后端数据能力**与**合理的功能切分**，从工程视角看是"合格的工具"。但 **从产品视角看，仍处在"功能完成 → 用户价值"之间的鸿沟**。

> 工具型应用最稀缺的不是功能，是 **信任感** 和 **节奏感**。
> 让一个非技术用户敢点 "清理" 按钮，敢关掉电脑不再担心数据丢失 —— 这才是从"能用"到"爱用"的真正跨越。

下一步建议：先做一份 `Onboarding + 零状态 + 错误态` 的设计稿（哪怕低保真），再进入开发。这样能一次性解决 PM 视角的"价值传达"、用户视角的"恐惧感"、UI 视角的"一致性"三大问题。
