# 架构设计

## 整体架构

```
┌─────────────────────────────────────────────────────┐
│                   Electron App                       │
│                                                      │
│  ┌─────────────────┐     ┌──────────────────────┐   │
│  │  Main Process    │     │  Renderer Process     │   │
│  │  (Node.js)       │ IPC │  (Chromium + React)   │   │
│  │                  │◄───►│                       │   │
│  │  DatabaseManager │     │  首页仪表盘  会话浏览  │   │
│  │  IPC 处理层      │     │  消息查看器  清理向导  │   │
│  │  better-sqlite3  │     │  备份恢复             │   │
│  └─────────────────┘     └──────────────────────┘   │
│                                                      │
│  contextIsolation: true  |  sandbox: true            │
│  nodeIntegration: false  |  渲染进程无法直接访问 Node │
└─────────────────────────────────────────────────────┘
```

## 进程分工

| 层 | 技术 | 职责 |
|----|------|------|
| **Main Process** | Node.js + better-sqlite3 | 打开/管理 SQLite 连接；执行所有读写 SQL；VACUUM / WAL checkpoint；文件备份/恢复；系统对话框 |
| **IPC Bridge** | contextBridge + ipcMain/ipcRenderer | 类型安全的通信通道；白名单校验；主进程暴露 API，渲染进程调用；请求/响应模式 |
| **Renderer** | React 18 + React Router 7 | 所有 UI 展示；不直接访问 SQLite 或文件系统；通过 `window.electronAPI.invoke()` 调用主进程 |
| **Shared** | TypeScript types | 共享 DTO 类型定义、IPC channel 常量 |

## 安全原则

- **contextIsolation: true** — 渲染进程不暴露 Node API
- **nodeIntegration: false** — 禁止渲染进程直接使用 Node.js
- **sandbox: true** — 启用沙箱模式
- 通过 `contextBridge` 暴露白名单 API，渲染进程只能调用已注册的方法
- preload 层对 IPC channel 做白名单校验，非 `ALLOWED_CHANNELS` 中的通道直接抛错
- SQLite 仅在主进程操作，渲染进程通过 IPC 请求数据
- 破坏性操作（删除 / VACUUM）必须经过「预览 → 确认」两步流程
- 备份删除操作校验文件路径必须在备份目录内，防止路径遍历攻击
- 会话列表排序字段做白名单校验，防止 SQL 注入

## 设计约束

- 渲染进程禁止 `require('better-sqlite3')` 或任何 Node 原生模块
- 所有文件系统操作（读写 .db、备份）均在主进程
- IPC 消息使用结构化 DTO，不传递原始 SQL 结果
- 不引入 ORM，使用参数化 SQL + DTO 映射
- 不引入 Redux，使用 React 本地状态管理
- 不引入 CSS-in-JS，使用 Tailwind CSS
- 不引入 ECharts，使用 Recharts

## 应用启动流程

1. `electron/main.ts` 创建 BrowserWindow，配置安全选项
2. 注册所有 IPC handler（各功能模块独立注册）
3. 自动检测默认数据库路径：
   - 优先: `~/.local/share/opencode/opencode.db`
   - 回退: `test-data/test.db`（开发环境）
4. 渲染进程加载后，Dashboard 组件通过 `database:health` 检查连接状态
5. 连接成功则并行加载所有仪表盘数据
6. 未连接则显示"Connect Database"引导页面

| `/cleanup` | Cleanup | 清理向导 |
| `/backup` | Backup | 备份恢复 |
