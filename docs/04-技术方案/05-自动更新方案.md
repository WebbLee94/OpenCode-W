# 05-自动更新方案

> **状态**：设计中
> **创建日期**：2026-07-07
> **目标版本**：OpenCode-W 1.2.x
> **作者**：Webb Lee

## 1. 背景与目标

### 1.1 背景

OpenCode-W 是 Electron 桌面应用，目前依赖用户**手动到 GitHub Releases 下载安装包**完成升级。痛点：

- 用户感知延迟（不知道有新版）
- 跨平台升级步骤各异（macOS 拖入 Applications / Windows 运行 NSIS / Linux 选 AppImage 或 .deb）
- 升级漏斗长，从"知道有新版"到"装上"流失率高

### 1.2 目标

1. 应用内**自动发现**新版本（后台静默）
2. 用户**主动触发**下载与安装（避免无签名场景下的静默安装被拦截）
3. 跨 3 平台（macOS / Windows / Linux）**统一体验**
4. 为未来**静默更新**留好演进路径（拿到代码签名后改 2 个配置项即可升级）

### 1.3 非目标（YAGNI）

- ❌ 「跳过此版本」能力
- ❌ 多更新通道（stable / beta / alpha）
- ❌ 下载进度取消
- ❌ 自动重试机制
- ❌ macOS / Windows 代码签名（本期不解决）

## 2. 关键约束

| 约束 | 说明 |
|------|------|
| **无代码签名** | macOS Gatekeeper 会拦截（用户需右键"打开"）；Windows UAC + SmartScreen 提示（用户需"仍要运行"） |
| **用户主动触发** | 启动后台静默检查，但不下载；用户点"立即更新"才下载；用户点"立即安装"才退出 App |
| **复用现有 release workflow** | 产物已发布到 GitHub Releases，自动发现复用即可 |
| **contextBridge 隔离** | 渲染层仅通过白名单 IPC 通道访问主进程 |

## 3. 方案选型

### 3.1 候选方案

| 方案 | 描述 | 取舍 |
|------|------|------|
| **A：`electron-updater`（手动模式）** | electron-builder 官方库，VS Code / Discord / GitHub Desktop 在用 | ✅ 跨平台一致 + 增量更新就绪 + 演进路径平滑；⚠️ 多 1 个依赖 |
| **B：自研 GitHub API + 原生下载** | 调 `api.github.com/repos/.../releases/latest` | ✅ 0 依赖；❌ 限流、资产匹配、SHA512 校验、平台细节全得自写 |
| **C：混合** | Linux AppImage 走 `electron-updater`，macOS/Windows 自研 | ⚠️ 两套代码路径长期维护 |

### 3.2 选型结论

**采用方案 A**。理由：
1. 与项目 `electron-builder` + GitHub Releases 生态同源
2. 跨平台心智模型一致
3. 拿到代码签名后改 `autoDownload` / `autoInstallOnAppQuit` 即可升级静默更新
4. 已被数千万级用户应用验证

### 4.1 系统拓扑

```
┌──────────────────────────────────────────────────────────┐
│                     Renderer (React)                      │
│  ┌──────────────┐  ┌────────────────┐  ┌──────────────┐  │
│  │ Sidebar 红点 │  │ Settings 页    │  │ UpdateDialog │  │

│         └───────── useUpdateStatus() ──────────┘          │
│                  (Context + Event subscription)           │
└────────────────────────┬─────────────────────────────────┘
                         │  IPC (contextBridge whitelisted)
┌────────────────────────▼─────────────────────────────────┐

│  ┌────────────────────────────────────────────────────┐  │

│  └─────────────────────┬──────────────────────────────┘  │
│                        │                                   │
│  ┌─────────────────────▼──────────────────────────────┐  │
│  │  electron-updater (manual mode)                    │  │
│  │  autoDownload=false / autoInstallOnAppQuit=false   │  │
│  │  publisher: GitHub (WebbLee94/OpenCode-W)          │  │
│  └─────────────────────┬──────────────────────────────┘  │
└────────────────────────┼─────────────────────────────────┘
                         │ HTTPS
                  ┌──────▼─────────┐
                  │ GitHub Releases │
                  │  (latest API)   │
                  └────────────────┘
```

### 4.2 关键边界

- **ContextBridge 隔离**：渲染层只通过 `IPC_CHANNELS.UPDATE_*` 调主进程
- **手动模式**：`autoDownload=false` + `autoInstallOnAppQuit=false` 确保无任何自动行为
- **GitHub Releases 原生**：复用现有 release workflow 产物

## 5. 状态机

`UpdateState` 是 5 态有限状态机：

```
              checkForUpdates()
        ┌──────────────────────────────┐
        ▼                              │
   ┌─────────┐   new version    ┌──────────────┐
   │  IDLE   │ ───────────────▶ │  AVAILABLE   │
   └─────────┘                  └──────┬───────┘
        ▲                              │ downloadUpdate()
        │                              ▼
        │                       ┌──────────────┐
        │                       │ DOWNLOADING  │
        │                       └──────┬───────┘
        │                              │ bytes=total
        │                              ▼
        │                       ┌──────────────┐
        │                       │ DOWNLOADED   │
        │                       └──────┬───────┘
        │                              │ quitAndInstall()
        │  app restarts                ▼
        └────────────────────────  ┌─────────┐
                                   │ INSTALL │
                                   └─────────┘
```

| # | 触发 | 主进程动作 | 渲染层反应 |
|---|------|-----------|------------|
| 1 | App 启动 +5s | `autoUpdater.checkForUpdates()` | 静默（无 UI） |
| 2 | GitHub 返回新版本 | `webContents.send('update:available', info)` | 侧边栏红点出现 |
| 3 | 用户进入 Settings | 读 `UpdateState` | 显示"有新版本 v1.2.1，点击下载" |
| 4 | 用户点"立即更新" | `IPC_UPDATE_DOWNLOAD` | 弹 UpdateDialog |
| 5 | 主进程开始下载 | `webContents.send('update:progress', n)` | 进度条更新 |
| 6 | 下载完成 | `webContents.send('update:downloaded', info)` | 按钮变"立即安装" |
| 7 | 用户点"立即安装" | `autoUpdater.quitAndInstall()` | App 退出 + 安装器启动 |
| 8 | 任何步骤失败 | `webContents.send('update:error', e)` | 弹窗显示错误 + 重试按钮 |

## 7. IPC 契约

### 7.1 Channel 命名

```ts
// shared/ipc-channels.ts 追加
UPDATE_CHECK: 'update:check',
UPDATE_DOWNLOAD: 'update:download',
UPDATE_INSTALL: 'update:install',
UPDATE_GET_STATE: 'update:get-state',

// 事件（main → renderer，单向推送）
UPDATE_EVENT_AVAILABLE: 'update:event:available',
UPDATE_EVENT_PROGRESS: 'update:event:progress',
UPDATE_EVENT_DOWNLOADED: 'update:event:downloaded',
UPDATE_EVENT_ERROR: 'update:event:error',
```

### 7.2 DTO 类型

```ts
// shared/types.ts 追加
export type UpdateState =
  | 'idle'
  | 'available'
  | 'downloading'
  | 'downloaded'
  | 'installing'

export interface UpdateInfo {
  version: string        // 远端版本号，semver
  releaseDate: string    // ISO 8601
  releaseNotes: string   // Markdown
  sizeBytes: number
}

export interface UpdateProgress {
  bytesPerSecond: number
  percent: number        // 0-100
  transferred: number
  total: number
}

export interface UpdateErrorPayload {
  code: 'network' | 'ratelimit' | 'no-asset' | 'download-failed' | 'install-failed' | 'unknown'
  message: string
}
```

## 8. 错误处理

| # | 错误场景 | 检测点 | 渲染层处理 |
|---|---------|--------|------------|
| 1 | **网络不可达** | `checkForUpdates()` reject / 客户端超时 30s | Toast：「检查更新失败：网络异常」（**本会话不再重试**，下次启动 App 时自动重试） |
| 2 | **GitHub API 限流** | 403 响应 | Toast：「检查更新失败：API 限流，请稍后再试」+ 重试按钮 |
| 3 | **下载中断** | `progress` 事件停止 > 60s | 弹窗：「下载中断，是否重试？」 |
| 4 | **平台资产缺失** | `latest.yml` 找不到对应 arch | Toast：「当前平台暂未提供更新包，请前往 GitHub Releases 手动下载」+ 跳转链接 |
| 5 | **macOS Gatekeeper 拦截** | NSAppleEventsUsageDescription | 由系统弹窗接管，应用层不处理 |
| 6 | **Windows UAC 拒绝** | NSIS 返回非 0 | Toast：「安装被取消」 |
| 7 | **已运行最新版** | `version === app.getVersion()` | 静默，状态机回 `IDLE` |

### 8.1 兜底

- **本地缓存**：`app.getPath('userData')/update-cache.json` 记录 `lastCheckedAt` + `lastVersion`
- **启动 5s 后单次检查**，连续失败不重试
- **事件去重**：同一 `version` 只更新一次状态

## 9. 测试策略

### 9.1 单元测试（Vitest）

| 模块 | 测试点 |
|------|--------|
| `update.ts` IPC handlers | mock `autoUpdater`，验证状态转换 + 事件正确发出 |
| `useUpdateStatus` Hook | `renderHook` 验证事件 → state 转换 |
| `UpdateState` 状态机 | 纯函数测试：禁止的转换抛错 |
| 错误分类器 | 给定 error code → 返回对应 UX 类型 |

### 9.2 集成测试（手动 Playwright + Electron）

- mock GitHub Releases API 注入"有新版" → 启动应用 → 验证红点出现
- mock `autoUpdater` 让下载在 30% 失败 → 验证"重试"按钮出现
- 已运行最新版 → 验证不弹 UI

### 9.3 端到端验证（手动，3 平台真实打包产物）

> **关键**：必须在真实打包产物上验证，不能只跑 `npm run dev`

| 平台 | 验证步骤 |
|------|---------|
| macOS | tag `v1.2.1-test` 触发 release → 下载并安装旧版 .dmg → 启动 → 验证更新提示 |
| Windows | 同上，NSIS 安装包 |
| Linux | AppImage：直接覆盖运行；.deb：`dpkg -i` 后启动 |

## 10. 实施步骤

按依赖顺序分 4 阶段，每阶段可独立提交 + review：

| 阶段 | 内容 | 提交类型 |
|------|------|---------|
| **P1** | 依赖 + 基础设施：`electron-updater` 装包 + `electron-builder.yml` `publish` + IPC 通道 + DTO + `update.ts` 骨架 | `chore` + `feat` |
| **P2** | 渲染层基础：`UpdateContext` + `useUpdateStatus` + `UpdateDialog`（只读）+ Settings 页 + UpdateSection 静态展示 | `feat` |
| **P3** | 联调：侧边栏红点 + UpdateDialog 接入下载/安装按钮 + 进度条 + Badge 嵌入 Sidebar | `feat` |
| **P4** | 错误处理 + 缓存：本地 JSON 缓存 + 错误分类器 + 重试按钮 + Toast 集成 + 测试 | `feat` + `test` |

### 10.1 风险

- **R1**：`electron-updater` 需在 `app.whenReady` 之后调用，延后到 `registerIpcHandlers()` 之后
- **R2**：dev 模式 `app.isPackaged === false` → 真实请求被跳过；需 `if (app.isPackaged)` 包裹检查逻辑
- **回退策略**：任一阶段出问题，git revert 即可，不影响现有功能

### 10.2 配置改动

`electron-builder.yml` 末尾新增：

```yaml
publish:
  provider: github
  owner: WebbLee94
  repo: OpenCode-W
  releaseType: release
```

## 12. 演进路径

拿到代码签名后：

| 现状 | 演进 |
|------|------|
| `autoDownload: false` | → `true`（静默下载） |
| `autoInstallOnAppQuit: false` | → `true`（退出时静默安装） |
| 渲染层手动触发 | → 仅首次启动提示 + 静默后台 |
| 无增量更新（macOS） | → 加上代码签名后自动启用 blockmap 增量 |
| 单通道 | → 引入 `beta` 通道供内测用户 |
