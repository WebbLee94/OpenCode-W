# 全文搜索方案

> 关联模块：[03-消息查看器.md](../03-功能模块/03-消息查看器.md)

## 一、设计目标

支持跨会话的消息内容全文搜索，1 秒内返回匹配结果。

## 二、搜索范围

| 数据源 | 字段 | 搜索方式 |
|--------|------|---------|
| session.title | 标题 | LIKE 模糊匹配 |
| message.data | 消息内容（JSON） | json_extract + LIKE |
| part.data | 片段内容（JSON） | json_extract + LIKE |

## 三、SQL 方案

### 3.1 标题搜索
```sql
SELECT id, title, time_updated
FROM session
WHERE title LIKE ? OR title LIKE ?
ORDER BY time_updated DESC
LIMIT ? OFFSET ?
```

### 3.2 消息内容搜索
```sql
SELECT m.id, m.session_id, json_extract(m.data, '$.content') AS content
FROM message m
WHERE json_extract(m.data, '$.content') LIKE ?
   OR json_extract(m.data, '$.text') LIKE ?
ORDER BY m.time_created DESC
LIMIT ? OFFSET ?
```

### 3.3 Part 内容搜索
```sql
SELECT p.id, p.message_id, p.session_id,
       json_extract(p.data, '$.text') AS text
FROM part p
WHERE json_extract(p.data, '$.text') LIKE ?
ORDER BY p.time_created DESC
LIMIT ? OFFSET ?
```

## 四、为何不用 FTS5

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| SQL LIKE | 零依赖、零维护 | 全表扫描、慢 | ✅ 采用（数据量可接受） |
| SQLite FTS5 | 性能好、支持分词 | 需建虚拟表、需维护索引、OpenCode 不提供 | ❌ 不采用 |

**理由**：
- OpenCode 数据库由 OpenCode 维护，OpenCode-W 不应修改 schema
- FTS5 需要触发器同步数据，增加复杂度
- 当前数据量（百万行 part）LIKE 搜索可在 1-2 秒完成，可接受
- 未来如需优化，可考虑外部索引（如内存索引）

## 五、性能优化

### 5.1 分页
- 默认 50 条/页，避免一次性返回过多结果
- 使用 LIMIT/OFFSET 分页

### 5.2 搜索结果高亮
- 前端用 `<mark>` 标签高亮匹配关键词
- 截取匹配位置前后 50 字符作为上下文

### 5.3 搜索建议
- 输入 2 字符后触发搜索
- 防抖 300ms

## 六、IPC 通道

| 通道 | 功能 | 入参 | 返回 |
|------|------|------|------|
| messages:search | 全文搜索 | { keyword, page, pageSize } | SearchResult[] |

## 七、未来优化方向

- 引入 FTS5 虚拟表（需评估对 OpenCode 的影响）
- 支持正则搜索
- 支持搜索范围筛选（仅标题/仅消息/仅 part）
- 搜索历史记录
