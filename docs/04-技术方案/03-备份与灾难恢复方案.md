# 备份与灾难恢复方案

> 关联模块：[05-备份恢复.md](../03-功能模块/05-备份恢复.md)

## 一、设计目标

提供一键备份、版本管理、灾难恢复能力，让用户像 Git commit 一样养成定期存档习惯。

## 二、备份策略

### 2.1 备份目录
- 默认：`~/.opencode-w/backups/`
- 每次备份创建独立子目录：`backup-YYYYMMDD-HHmmss/`
- 内含：opencode.db 副本 + manifest.json（元数据）

### 2.2 备份方式
- **全量备份**：复制整个 opencode.db 文件（含 WAL）
- 触发：用户手动点击「创建备份」
- 自动备份调度：v1.1.0 已移除（评估为非核心）

### 2.3 manifest.json 结构
```json
{
  "createdAt": "2026-07-07T10:00:00Z",
  "dbPath": "~/.local/share/opencode/opencode.db",
  "dbSize": 844000000,
  "sessionCount": 2858,
  "version": "1.2.0"
}
```

## 三、版本管理

- 备份列表按时间倒序展示
- 显示：时间、大小、会话数、操作（恢复/删除/预览）
- 不自动清理旧备份（用户手动管理）

## 四、恢复流程

1. 用户选择备份 → 点击「恢复」
2. 弹出确认对话框（预览备份信息）
3. 确认后：
   - 关闭当前数据库连接
   - 复制备份文件到目标路径
   - 重新打开数据库
   - 刷新所有页面数据

## 五、安全设计

### 5.1 路径遍历防护
```typescript
// 校验备份文件路径必须在备份目录内
const backupDir = path.resolve(this.getBackupRoot())
const targetPath = path.resolve(backupDir, req.name)
if (!targetPath.startsWith(backupDir + path.sep)) {
  throw new Error('非法路径')
}
```

### 5.2 恢复前确认
- 显示备份时间、大小、会话数
- 3 秒倒计时按钮（防止误操作）
- 当前数据库会被覆盖警告

## 六、IPC 通道

| 通道 | 功能 | 入参 | 返回 |
|------|------|------|------|
| backup:create | 创建备份 | void | BackupInfo |
| backup:list | 列出备份 | void | BackupInfo[] |
| backup:restore | 恢复备份 | name | { success } |
| backup:delete | 删除备份 | name | { success } |
| backup:preview | 预览备份 | name | BackupDetail |

## 七、灾难恢复场景

| 场景 | 恢复方式 |
|------|---------|
| 误删会话 | 从最近备份恢复 |
| 数据库损坏 | 从备份恢复 + VACUUM |
| 清理操作误执行 | 从清理前备份恢复 |
| 升级失败回滚 | 从升级前备份恢复 |
