# 数据访问层

## 设计原则

数据库可能达到数百 MB，`part` 表可达数十万行——

- **所有查询必须分页**
- **所有写操作必须显式确认**
- **不用 ORM，用参数化 SQL + DTO**

## DatabaseManager

核心单例类，管理所有 SQLite 连接：

```typescript
class DatabaseManager {
  private static instance: DatabaseManager | null = null
  private connections: Map<string, Database.Database> = new Map()
  private currentPath: string | null = null

  // 单例获取
  static getInstance(): DatabaseManager

  // 连接管理
  open(dbPath: string): Database.Database   // 打开数据库，启用 WAL + 外键
  close(dbPath?: string): void              // 关闭指定或当前连接
  getDb(): Database.Database                // 获取当前数据库实例
  getCurrentPath(): string | null           // 获取当前数据库路径
  closeAll(): void                          // 关闭所有连接

  // 健康检查
  healthCheck(): { ok: boolean; pageCount: number; freelistPages: number; walSize: number }

  // 统计
  getStats(): DatabaseStats                 // 数据库概览统计
  getTableStats(): TableStats[]             // 各表行数和数据大小

  // 维护操作
  vacuum(): { before: number; after: number; freed: number }
  checkpoint(): void                        // WAL checkpoint (TRUNCATE)

  // 通用查询
  rawQuery<T>(sql: string, params?: unknown[]): T[]
  rawGet<T>(sql: string, params?: unknown[]): T | undefined
  run(sql: string, params?: unknown[]): { changes: number; lastInsertRowid: number }
}
```

**关键行为**：
- 打开时自动设置 `journal_mode = WAL`、`foreign_keys = ON`
- 单连接模式（WAL 下足够，避免锁竞争）
- `Map<路径, 连接>` 支持同时管理多个 `.db` 文件
- 打开前校验文件是否存在
- 重复打开同一路径时先关闭旧连接

## 查询模式

不用 ORM，用「参数化 SQL + DTO 映射」：

### 会话列表 — 分页 + 聚合

```typescript
const rows = dbManager.rawQuery<Record<string, unknown>>(
  `SELECT
    s.*,
    COALESCE(msg_cnt.cnt, 0) as msg_count,
    (COALESCE(s.tokens_input, 0) + COALESCE(s.tokens_output, 0) + COALESCE(s.tokens_reasoning, 0)) as total_tokens,
    COALESCE(part_size.total, 0) as data_size
  FROM session s
  LEFT JOIN (SELECT session_id, COUNT(*) as cnt FROM message GROUP BY session_id) msg_cnt ON s.id = msg_cnt.session_id
  LEFT JOIN (SELECT session_id, SUM(LENGTH(data)) as total FROM part GROUP BY session_id) part_size ON s.id = part_size.session_id
  ${whereClause}
  ORDER BY s.${safeSortBy} ${safeSortOrder}
  LIMIT ? OFFSET ?`,
  [...params, pageSize, offset]
)
```

### Token 统计

```typescript
const row = dbManager.rawGet<Record<string, number>>(
  `SELECT
    COALESCE(SUM(tokens_input), 0) as inputTokens,
    COALESCE(SUM(tokens_output), 0) as outputTokens,
    COALESCE(SUM(tokens_reasoning), 0) as reasoningTokens,
    COALESCE(SUM(tokens_cache_read), 0) as cacheRead,
    COALESCE(SUM(tokens_cache_write), 0) as cacheWrite,
    COALESCE(SUM(cost), 0) as estimatedCost
  FROM session`
)
```

### 工具使用排行

```typescript
const rows = dbManager.rawQuery<Record<string, unknown>>(
  `SELECT
    COALESCE(json_extract(data, '$.tool_name'), 'unknown') as toolName,
    COUNT(*) as count
  FROM part
  WHERE type = 'tool'
  GROUP BY toolName
  ORDER BY count DESC
  LIMIT 20`
)
```

### 技能使用分布

```typescript
const rows = dbManager.rawQuery<Record<string, unknown>>(
  `SELECT
    COALESCE(json_extract(data, '$.skill_name'), 'unknown') as skillName,
    COUNT(*) as count
  FROM part
  WHERE type = 'tool'
    AND json_extract(data, '$.tool_name') = 'skill'
  GROUP BY skillName
  ORDER BY count DESC
  LIMIT 20`
)
```

### 增长趋势

```typescript
// 按天聚合会话数
const sessionRows = dbManager.rawQuery(
  `SELECT date(time_created / 1000, 'unixepoch') as date, COUNT(*) as newSessions
   FROM session GROUP BY date ORDER BY date ASC`
)

// 按天聚合消息数
const messageRows = dbManager.rawQuery(
  `SELECT date(time_created / 1000, 'unixepoch') as date, COUNT(*) as messageCount
   FROM message GROUP BY date ORDER BY date ASC`
)

// 累计数据增长
const daySizeRow = dbManager.rawGet(
  `SELECT COALESCE(SUM(LENGTH(data)), 0) as total FROM part
   WHERE date(time_created / 1000, 'unixepoch') = ?`,
  [date]
)
```

## 破坏性操作安全流

```
渲染进程                          主进程
  │                               │
  │── cleanup:preview(filter) ───►│  只读，计算影响范围
  │◄── CleanupPreviewDTO ─────────│  { sessionCount, messageCount, partCount, estimatedSize, sessions }
  │                               │
  │  [用户可逐个取消勾选会话]       │
  │                               │
  │── cleanup:execute(filter) ───►│  删除 part → message → session → VACUUM
  │◄── CleanupResultDTO ──────────│  { deletedSessions, deletedMessages, deletedParts, freedBytes, vacuumBefore, vacuumAfter }
```

**安全措施**：
- 预览阶段只读，不修改任何数据
- 会话列表可逐个取消勾选（`excludedSessionIds`）
- 确认步骤必须勾选「已备份」复选框
- 确认按钮有 3 秒倒计时防止误点击
- 执行后自动触发 VACUUM 回收空间

## 清理 SQL 执行顺序

```sql
-- 1. 先删除 part
DELETE FROM part WHERE session_id IN (SELECT id FROM session WHERE <筛选条件>);

-- 2. 删除 message
DELETE FROM message WHERE session_id IN (SELECT id FROM session WHERE <筛选条件>);

-- 3. 删除 session
DELETE FROM session WHERE <筛选条件>;

-- 4. 回收空间
VACUUM;
```

## SQL 注入防护

- 排序字段使用白名单校验：`allowedSortColumns = ['time_created', 'time_updated', 'title', 'cost', 'msg_count', 'total_tokens', 'data_size', 'tokens_input', 'tokens_output']`
- 搜索条件使用参数化查询：`WHERE title LIKE ?`
- 自定义 WHERE 条件（清理向导）由用户自行承担风险，UI 提示表别名 `s=session`
- 备份文件路径校验：`resolvedPath.startsWith(path.resolve(BACKUP_DIR))`

## 性能考量

| 查询 | 估算耗时 | 策略 |
|------|---------|------|
| Dashboard 概览 | <100ms | 聚合 session 列，不扫描大表 |
| Token 统计 | <100ms | SUM 聚合 session 表 |
| Tool 排行 | ~200ms | `json_extract` + GROUP BY 全扫描 part |
| Skill 分布 | ~200ms | `json_extract` + GROUP BY 全扫描 part |
| Session 列表（分页） | <50ms | LEFT JOIN 子查询 + LIMIT 限制 |
| Session 详情 | <50ms | 主键查询 + 聚合 |
| Message 列表（单会话） | <30ms | session_id 索引 + LIMIT |
| Message 详情 | <10ms | 主键查询 |
| 清理预览 | ~200ms | 多次聚合查询 |
| 清理执行 | 视数据量 | 批量 DELETE + VACUUM |

数十万 part 行在本地 SQLite 上完全可控，无需额外索引。Dashboard 统计数据可在主进程内存中缓存，避免重复查询。
