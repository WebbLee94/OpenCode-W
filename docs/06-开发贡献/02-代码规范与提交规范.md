# 代码规范与提交规范

## 一、TypeScript 规范

- 严格模式（`strict: true`，见 tsconfig.json）
- 禁止 `any`，必须显式类型
- 优先使用 `interface`，需联合类型时用 `type`
- DTO 定义在 `shared/types.ts`，跨进程共享

## 二、ESLint 规范

- 配置文件：`.eslintrc.cjs`
- 提交前必须通过 `npm run lint`
- 关键规则：
  - no-unused-vars
  - no-explicit-any
  - react-hooks/exhaustive-deps

## 三、React 规范

- 函数组件 + Hooks
- 状态管理：Zustand（不引入 Redux）
- 样式：Tailwind CSS（不引入 CSS-in-JS）
- 图表：Recharts（不引入 ECharts）
- 路由：React Router 7

## 四、SQL 规范

- 所有查询必须参数化（`?` 占位符）
- 禁止字符串拼接 SQL
- 排序字段需白名单校验（防 SQL 注入）
- 分页必须使用 LIMIT/OFFSET

## 五、安全规范

- contextIsolation: true
- nodeIntegration: false
- preload 输出为 .cjs（非 .mjs）
- 破坏性操作必须预览+确认+倒计时
- 文件路径校验防遍历攻击

## 六、Git 提交规范

### 6.1 Conventional Commits

```
feat:     新功能
fix:      修复 Bug
refactor: 重构（不改变功能）
test:     测试相关
docs:     文档更新
chore:    构建/工具链调整
perf:     性能优化
ci:       CI 配置
style:    代码风格（不影响功能）
```

### 6.2 提交信息规则（来自 .trae/rules/git-commit-message.md）

- 必须以动词开头（feat/fix/refactor 等）
- 必须是中文
- 必须是单行
- 聚焦"为什么"而非"做了什么"

### 6.3 示例

✅ 好：
```
feat(sessions): 添加会话批量迁移能力
fix(electron/ipc): 完善git仓库sha1计算的异常处理
docs: 重构docs目录结构为8维度分类
```

❌ 坏：
```
update file                    # 无类型前缀
added new feature for sessions # 英文
feat: 修改了sessions.tsx       # 聚焦"做了什么"而非"为什么"
```

## 七、禁止事项

- ❌ 不引入 ORM（Drizzle/Prisma）
- ❌ 不引入 Redux
- ❌ 不引入 ECharts
- ❌ 不在渲染进程直接访问 node:sqlite
- ❌ 不将 preload 输出为 .mjs
- ❌ 不启用 renderer: {} 配置
