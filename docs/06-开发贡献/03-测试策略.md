# 测试策略

## 一、测试分层

| 层级 | 工具 | 范围 | 运行命令 |
|------|------|------|---------|
| 单元测试 | Vitest | 工具函数、纯逻辑 | npm run test |
| E2E 测试 | Playwright | 跨进程交互 | npx playwright test |
| 类型检查 | tsc | 全项目类型 | npx tsc --noEmit |
| Lint | ESLint | 代码规范 | npm run lint |

## 二、单元测试规范

### 2.1 文件命名
- 测试文件：`*.test.ts` 或 `*.test.tsx`
- 与被测文件同目录（如 `src/lib/format.test.ts` 测 `src/lib/format.ts`）

### 2.2 测试组织
```typescript
import { describe, it, expect } from 'vitest'
import { formatBytes } from './format'

describe('formatBytes', () => {
  it('应正确格式化字节', () => {
    expect(formatBytes(1024)).toBe('1 KB')
  })

  it('应处理 0 字节', () => {
    expect(formatBytes(0)).toBe('0 B')
  })
})
```

### 2.3 覆盖率目标
- 工具函数：≥ 90%
- 业务逻辑：≥ 80%
- UI 组件：可视情况，重点测交互逻辑

## 三、E2E 测试规范（Playwright）

### 3.1 测试范围
- 关键用户流程：启动 → 仪表盘 → 会话浏览 → 消息查看
- 破坏性操作：清理向导预览+确认流程
- 备份恢复：创建备份 → 恢复 → 验证

### 3.2 测试数据
- 使用 `npm run generate-fixture` 生成测试数据库
- 不依赖真实 opencode.db

## 四、测试数据生成

```bash
npm run generate-fixture
```

生成 `test-data/test.db`，包含：
- 3 个项目
- 50 个会话（含 10 个父子会话）
- 500 条消息
- 2000 个 part（覆盖 12 种类型）

## 五、CI 中的测试

```yaml
# .github/workflows/ci.yml 关键步骤
- run: npm ci
- run: npx tsc --noEmit
- run: npm run lint
- run: npm run test
- run: npm run build
```

## 七、测试原则

- TDD 优先：新功能先写测试再实现
- 测试应独立：不依赖执行顺序
- 测试应快速：单元测试 < 10 秒
- 测试应可重复：相同输入相同输出
