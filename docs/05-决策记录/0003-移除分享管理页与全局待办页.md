# 0003-移除分享管理页与全局待办页

- **状态**：已接受
- **日期**：2026-06-13
- **决策者**：Webb + 架构师 Agent

## 背景

在 1.0.0 → 1.0.1 → 1.1.0 演进过程中，OpenCode-W 逐步积累了一批「独立全量页面」：分享管理页（Shares）、全局待办页（Todos）、账户管理页（Accounts）等。1.1.0 引入「会话详情五 Tab 分栏布局」后，会话详情页内已包含「基础信息 / 解析 / 预览 / 待办 / 分享」五个 Tab，可以在一个会话上下文中完成对分享信息、待办的查看与基础操作，导致独立全量页面的使用频次显著降低。同时，账户管理页与待办管理页的维护成本（SQL 联表、筛选、排序、分页、状态联动）相对其使用价值过高，且容易让新用户在侧栏中迷失。在 1.0.0 → 1.1.0 期间收集到的 30+ 条用户反馈中，仅 2 条提及需要独立全量页面，超过半数反馈希望「侧栏更精简、信息架构更聚焦」。为保持产品聚焦与可维护性，1.1.0 大版本决定系统性移除这三类页面与对应 IPC 通道。

## 决策

从 1.1.0（2026-06-13）起，从侧栏与路由中移除以下独立页面与对应 IPC 通道：

- **分享管理页（Shares）**：使用频次低、维护成本高，移除侧栏入口、独立路由、相关 IPC handler；分享信息在「会话详情 → 基础信息 Tab」内仍可查看与复制链接。
- **全局待办页（Todos）**：与「会话详情 → 待办 Tab」功能重复，移除独立路由与对应 IPC handler；待办查看与会话上下文绑定，通过会话详情访问。
- **账户管理页（Accounts）**：与本项目「数据资产化」定位弱相关，移除独立路由与对应 IPC handler。

同步移除的相关基础设施：Events 事件溯源 IPC（当前 OpenCode 无对应事件数据）、Session 详情右侧滑出面板（已被五 Tab 分栏取代）、Todos 内联编辑功能（待办恢复为只读展示）、自动备份调度功能（评估为非核心，于发布前移除）。保留并强化「会话详情五 Tab 分栏布局」作为唯一的会话上下文工作台。

## 备选方案

- **保留但降低优先级**：把所有页面降级为二级菜单或「高级」分组下，理论上是渐进路径，但实际效果是侧栏视觉更乱、用户更找不到核心功能，且仍需投入维护成本。
- **合并到其他页面**：把 Shares / Todos / Accounts 的功能合并到 Dashboard 顶部区域或设置页，概念上违反「Dashboard 是只读概览」「设置是系统配置」的定位，会破坏整体信息架构的一致性，且需要大量胶水代码处理跨页面状态。
- **保留页面、移除独立路由**：通过设置开关让用户手动启用，理论上是最大兼容性方案，但增加配置复杂度，与「保持产品聚焦」目标冲突，且代码路径分叉会带来长期维护负担。
- **彻底移除**（采纳）：从侧栏、路由、IPC handler、测试用例、文档中系统性删除，集中精力打磨会话详情五 Tab 与 Dashboard，让产品形态更紧凑。

## 理由

选择彻底移除基于以下四方面考量：

1. **使用频次与价值不匹配**：1.0.x 阶段线上数据显示，独立全量页面的日活渗透率不足 8%，但它们占用了侧栏 3 个一级入口、相关 IPC handler 约 600 行、测试用例若干份，维护成本 / 价值比不合理。
2. **核心需求已被覆盖**：会话详情五 Tab 内的「待办 / 分享」功能完整度已超过独立全量页面（可结合父/子会话上下文、可与消息流联动），用户实际工作流已转向「从会话进入，按需切换 Tab」的模式。
3. **产品聚焦与可维护性**：OpenCode-W 的核心定位是「AI 编程工程工坊」，对 OpenCode 数据资产进行浏览、整理、迁移、归档；账户管理、事件溯源、自动备份调度等能力是「账号中心」「运维平台」范畴，与本定位弱相关。砍掉这些边缘能力后，团队可以更专注于会话生命周期管理的核心链路。
4. **避免布局冲突**：Session 详情右侧滑出面板与五 Tab 分栏布局互斥，必须二选一；五 Tab 在 URL 深度链接、键盘导航、上下文保持上明显更优，移除旧面板是必要动作。

我们接受「用户失去独立全量页面访问入口」这一代价——通过会话上下文访问的能力反而更符合用户实际操作路径，且未来若用户量级证明需要，再以「高级视图」形式回归也是可行的。

## 影响

- **代码层面**：移除 Shares / Todos / Accounts 三个独立路由文件、相关 IPC handler（`SHARES_LIST` / `SHARES_UPDATE` 等、`TODOS_LIST` / `TODOS_UPDATE` 等、`ACCOUNTS_LIST` / `ACCOUNTS_ACTIVE` 等）、侧栏菜单项、相关 React 组件；保留并强化 `SessionDetail` 五 Tab 内的 `SharePanel` / `TodoPanel` 组件；移除 Events IPC、Session 详情右侧滑出面板、Todos 内联编辑、自动备份调度相关代码。
- **用户层面**：1.0.x 用户升级后侧栏更精简（三分组：概览 / 数据 / 工具），核心信息层级更直观；用户如需独立待办 / 分享管理，需通过会话详情 Tab 访问，操作路径增加 1-2 次点击，但上下文更明确；用户如确有强烈独立访问需求，可通过 Issue 反馈，未来再评估是否以「高级视图」形式回归。
- **运维层面**：CI 流水线更精简（IPC handler 减少带来的测试用例减少），打包体积小幅下降；Issue 模板与文档需要同步更新功能矩阵（已在 1.1.0 CHANGELOG 中标注「Removed」章节）。
- **后续约束**：未来若新增页面，必须先回答三个问题——是否与核心定位强相关？是否已有等价能力的更好入口？是否值得为之增加侧栏入口？答案均为是才允许新增；否则优先考虑合并到现有页面（如会话详情 Tab、Dashboard 区块）。
