# DBScope-OC 用户手册

## 1. 安装与启动

### 1.1 系统要求

| 要求 | 最低版本 |
|------|---------|
| 操作系统 | macOS 12.0 或更高版本 |
| Node.js | 18.0 或更高版本 |
| npm | 随 Node.js 安装 |

### 1.2 开发模式启动

```bash
# 1. 进入项目目录
cd DBScope-OC

# 2. 安装依赖
npm install

# 3. 生成测试数据（首次使用建议执行）
npm run generate-fixture

# 4. 启动开发模式
npm run dev
```

启动后 Electron 窗口会自动打开。应用会自动检测默认数据库路径，如果找到 `~/.local/share/opencode/opencode.db` 会自动连接；否则尝试连接 `test-data/test.db`。

### 1.3 打包安装

```bash
# 构建并打包为安装程序
npm run build
```

打包产物在 `dist/` 目录下，macOS 会生成 `.dmg` 安装包。

### 1.4 其他命令

| 命令 | 说明 |
|------|------|
| `npm run lint` | 代码规范检查 |
| `npm run preview` | 预览构建产物 |
| `npm run test` | 运行测试 |
| `npx tsc --noEmit` | 类型检查 |

## 2. 首次使用

### 2.1 自动检测 opencode.db

应用启动时会自动检测以下路径：

1. **默认路径**：`~/.local/share/opencode/opencode.db`
2. **测试数据库**：`test-data/test.db`（仅开发环境）

如果找到数据库，左侧边栏底部会显示绿色圆点 + "已连接"。

### 2.2 手动打开数据库文件

如果自动检测未找到数据库，或需要打开其他数据库：

1. 点击左侧边栏底部的"打开数据库"按钮
2. 在文件选择对话框中选择 `.db` / `.sqlite` / `.sqlite3` 文件
3. 连接成功后页面自动刷新

## 3. 功能使用

### 3.1 首页仪表盘

首页仪表盘提供数据库全貌概览。

**统计卡片**（两行，每行 4 个）：

| 第一行 | 第二行 |
|--------|--------|
| 总大小（数据库文件大小） | WAL 日志大小 |
| 会话数 | Part 行数 |
| 项目数 | 估算成本（美元） |
| 可回收碎片 | 缓存命中率 |

**图表区域**：

- **Token 分布**：环形饼图展示输入/输出/推理 Token 比例
- **工具使用排行 TOP 10**：横向柱状图
- **技能使用分布**：横向柱状图
- **增长趋势**：双 Y 轴折线图（新会话数 + 数据增长）

**快速操作**：

| 按钮 | 功能 | 说明 |
|------|------|------|
| 一键 VACUUM | 回收碎片空间 | 执行 VACUUM 命令，释放 freelist 中的空间 |
| WAL Checkpoint | 合并 WAL 日志 | 将 WAL 文件内容写回主数据库文件 |
| 刷新 | 重新加载数据 | 重新拉取所有仪表盘数据 |

### 3.2 会话浏览

会话浏览页面以表格形式展示所有会话。

**筛选功能**：

- **搜索**：输入关键词搜索会话标题或 ID（300ms 防抖）
- **项目筛选**：下拉选择特定项目
- **排序**：支持按最近活跃、标题、消息数、数据大小、Token 消耗排序
- **排序方向**：升序/降序切换

**表格列**：

| 列 | 说明 |
|----|------|
| 标题 | 会话标题，截断显示 |
| 消息数 | 该会话的消息数量 |
| 数据大小 | 关联 Part 数据的总大小 |
| Token 消耗 | 输入 + 输出 Token 总和 |
| 最近活跃 | 最后更新时间的相对表示 |
| 所属项目 | 项目标识 |

**详情面板**：

点击表格行，右侧滑出详情面板（480px），展示：
- 基础信息（目录、模型、时间范围）
- Token 明细（环形饼图 + 各项数值）
- Tool 使用排行（横向柱状图 TOP 5）
- Skill 列表（紫色标签）
- 操作按钮：查看消息 / 删除此会话

**分页**：默认 50 条/页，支持页码输入跳转。

### 3.3 消息查看器

消息查看器采用左右分栏布局，从会话浏览页点击"查看消息"进入。

**左侧 - 消息列表**（40% 宽度）：
- 显示消息序号、角色图标、数据大小、时间
- 大小颜色编码：< 20KB 灰色，20-50KB 红色，> 50KB 粗体红色
- 分页浏览（50 条/页）

**右侧 - 消息详情**（60% 宽度）：
- 角色徽章 + 时间 + 大小
- 内容渲染：
  - 用户消息：蓝色背景纯文本
  - AI 消息：Markdown 渲染（支持 GFM、代码高亮）
  - 错误消息：红色背景
- Part 筛选：全部 / text / tool / reasoning
- Part 明细表：类型徽章 + 大小 + 摘要
- 可展开的 Part 详情：
  - 🔧 Tool：工具名 + 状态 + 输入参数 + 输出内容
  - 🧠 Reasoning：推理过程文本
  - ✅ Step-finish：Token 使用明细（Input/Output/Reasoning/Cache）

### 3.4 清理向导

清理向导采用 3 步安全流程，确保数据不会误删。

**步骤 1：选择策略**

| 策略 | 说明 | 参数 |
|------|------|------|
| 按时间 | 删除指定天数前的旧会话 | 天数（默认 90） |
| 按大小 | 删除数据量超过阈值的会话 | 大小 MB（默认 50） |
| 按项目 | 删除指定项目的所有会话 | 项目名（下拉选择） |
| 自定义 | 使用 SQL WHERE 条件 | WHERE 子句 |

**步骤 2：预览影响范围**

- 4 个彩色统计卡片：将删除会话数（红）、消息数（橙）、Part 数（黄）、预计释放空间（紫）
- 会话列表可逐个取消勾选
- 全选/全不选快捷操作
- 统计数据根据勾选状态动态更新
- 黄色警告：建议执行前先备份数据库

**步骤 3：确认执行**

- 显示最终清理范围摘要
- 红色警告：此操作不可逆
- 必须勾选"我已确认备份了数据库"
- 3 秒倒计时防止误点击
- 执行后显示清理结果（删除行数、释放空间、VACUUM 结果）

### 3.5 备份恢复

**创建备份**：
- 点击"立即备份"按钮
- 备份文件自动保存到 `~/.DBScope-OC/backups/`
- 文件命名格式：`opencode-backup-YYYY-MM-DDTHH-MM-SS-mmmZ.db`
- 同时复制 WAL 和 SHM 文件

**查看备份列表**：
- 表格展示：文件名、大小、创建时间、压缩状态
- 按时间降序排列
- 支持刷新

**恢复数据库**：
1. 点击备份行的"恢复"按钮
2. 弹出对话框，预览备份内容（会话数/消息数/Part 数）
3. 确认恢复
4. 应用会关闭当前连接，打开备份文件作为新数据库

**删除备份**：
1. 点击备份行的"删除"按钮
2. 确认删除（不可撤销）

## 4. 常见问题

### 4.1 数据库锁定怎么办

**症状**：操作时提示 "database is locked"

**解决方案**：
1. 确保没有其他程序正在访问同一个数据库文件
2. 尝试执行 WAL Checkpoint（仪表盘页面）
3. 关闭应用后重新打开
4. 如果问题持续，检查是否有 OpenCode 进程正在运行

### 4.2 清理后空间未释放

**原因**：SQLite 删除数据后不会自动回收磁盘空间，freelist 页面保留供后续写入使用。

**解决方案**：
1. 在仪表盘页面点击"一键 VACUUM"
2. 清理向导执行后会自动触发 VACUUM
3. VACUUM 会重建数据库文件，释放未使用的空间

### 4.3 备份文件存储位置

备份文件存储在应用的用户数据目录下：

| 操作系统 | 路径 |
|---------|------|
| macOS | `~/.DBScope-OC/backups/` |
| Linux | `~/.DBScope-OC/backups/` |
| Windows | `~/.DBScope-OC/backups/` |

### 4.4 默认数据库路径

OpenCode 的默认数据库路径为：

```
~/.local/share/opencode/opencode.db
```

应用启动时会自动检测此路径。如果不存在，开发模式下会尝试连接 `test-data/test.db`。

### 4.5 如何生成测试数据

```bash
npm run generate-fixture
```

此命令会在 `test-data/` 目录下生成 `test.db` 测试数据库，包含模拟的会话、消息和 Part 数据。

### 4.6 恢复数据库后页面未更新

恢复数据库后，建议刷新页面（Cmd+R）或重启应用，以确保所有缓存数据被清除。
